Slack Protocol Handler

yuyu
2026-11-19
Slack, deep-link

e.g. SetWindowOpenHandler

Deep link handling works as shown above.

eR: the HANDLE_DEEP_LINK action creator.

It builds an action (payload: { url }), which is then consumed by 1 reducer + 5 epics.

Reducer

It reads the ?team= value from the deep link, and only when that team already exists in the list of logged-in workspaces (teamsByIndex) does it change selectedTeamId to that team, switching the workspace shown on screen.

If there is no team parameter, or the team is unknown, it leaves the state as is (no-op). In other words, the reducer is a pure state change that only “switches focus to the team the deep link points to”; the actual side effects (settings / app actions / forwarding to the webapp) are handled by the epics.

Epics

  1. FORWARD_DEEP_LINK_TO_WEBAPP

Handles the case where team is empty or is an already logged-in workspace. It finds the already-loaded webapp renderer for that workspace and passes the deep link over IPC (FORWARD_DEEP_LINK) so the in-app logic can handle things like channel/message navigation.

  1. TRANSFORM_DEEP_LINKS

Handles the case where a team is present but not yet logged in (unknown). It reverse-searches the workspaces I’m logged into for one that contains that team (preferring the currently selected workspace, otherwise scanning all of them). If found, it reassembles the deep link URL for that workspace (slack://<cmd>?team=<resolved team>&...) and dispatches it back through eR.

  1. UPDATE_SETTINGS_VIA_DEEP_LINKS

→ Settings are applied after only passing through the allowlist + value validation. If clientEnvironment is included, it returns an empty dist entirely. (Covered in SWITCH_CLIENT_FEATURE_MODE_VIA_DEEP_LINKS.)

It directly sets f7 settings such as launchOnStartup, startNetLogAtLaunch, releaseChannelOverride.

  • dh()

    It parses the value from a single ?update=<JSON> parameter.

    e.g. slack://settings?update={"startNetLogAtLaunch":true,"runFromTray":false}

  1. SWITCH_CLIENT_FEATURE_MODE_VIA_DEEP_LINKS

When clientEnvironment is present on its own, it’s properly handled here. It uses the same dh function to parse.

  1. APP_ACTIONS_VIA_DEEP_LINKS

A slack://app?action=something link passes through without any confirmation.

Findings

  1. Unconfirmed app actions (APP_ACTIONS_VIA_DEEP_LINKS)
  • slack://app/?action=quit
  • slack://app/?action=reset-window

Clicking links like these executes them without confirmation.

  1. Unconfirmed settings changes (in the allowlist, f7)
Setting Effect
startNetLogAtLaunch START_NET_LOG_AT_LAUNCH checks this flag right after boot and auto-starts network capture. When it finishes, it resets back to false.
launchOnStartup Auto-launches Slack on OS login (persistent).
releaseChannelOverride value=prod(default)/beta/dogfood. Decides which build Slack pulls via auto-update.
hideOnStartup When started via auto-launch, starts hidden without showing the window.
runFromTray Stays resident in the tray even when the window is closed.
clientEnvironment (used alone) Changes the client trust tier (NORMAL/RESTRICTED/MILITARY).
